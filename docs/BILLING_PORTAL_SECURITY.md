# Billing management
The production account page provides self-service billing using provider-generated subscription management links with any bearer token stripped. Paddle authenticates via the billing email. We deliberately do not call portal-sessions to issue an authenticated customer-wide session to passkey-only accounts: Paddle reuses customers based on checkout email, which CourseAccess has not independently verified. This would expose customer-wide billing data to the wrong account. A separate verified email identity and safe linking flow is required before enabling seamless sessions. Customers may also use their Paddle receipt. This implementation does not collect money. Production deployment now requires catalog migration 0007. Official reference: https://developer.paddle.com/build/customers/integrate-customer-portal/ and https://developer.paddle.com/build/customers/create-update-customers/.
